# 設計

ML-Quest の設計の方針をまとめる.

## 目的

機械学習をもとにした課題解決のために, 問題を設定するライブラリ.

機械学習は課題を解く手段の 1 つにすぎない. 推論や学習がゴールになるのを防ぐため, 課題から始めて, 課題を分解し, どの部分を機械学習に任せると課題の解決につながるかの筋道を, 1 つのファイル (問題の設定) に残す. 後ろの段階 (データの分析, モデルの作成, 学習・評価, 推論) が要る値 (目的の列, タスク, 使ってよい列, 評価の指標, 意思決定の損得と制約) は, 全てこの筋道から出る.

- **問い**: 問題の設定を決まった順の問いで埋める. 問いの並びと中身はこのライブラリが持ち, 画面 (ML-Pathfinder) はそれを順に出すだけ
- **確かめ**: 答えどうしの食い違い (量を決めるのに分類のタスク, 予測の時点で分からない列を使う, など) と, 足りない答えを一覧にする
- **受け渡し**: 後ろの段階ごとに, 問題の設定から決まる値をまとめて返す
- **骨組み**: 問題の設定から, 学習・評価の段階 (ML-Found) のプロジェクトの骨組み (config と学習のスクリプト) を書き出す
- **機械学習を使わない出口**: 課題の分解の結果, 機械学習が要らない (ルールや集計, 今のやり方の改善で足りる) と分かれば, そこで終えられる. 問題の設定は機械学習の入口ではなく, 機械学習が要るかを決める場所

## 全体の中での役割

「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「問題の設定」の段階でライブラリを受け持つ. 画面は ML-Pathfinder.

- **作る約束**: 問題の設定のファイル (`problem.yaml`, `format_version` 付き. 下の「問題の設定の形」). 形はこのライブラリが持つ. 型の値の名前 (受け持ち, 1 件の単位, 出力の形, 正解の出どころ, 作り方, 正解の種類) もこのライブラリが持ち, 他の段階は写して使う
- **書き出すもの**: ML-Found のプロジェクトの形 (ML-Found の `docs/FORMAT.md` の「プロジェクトの形」) の骨組み. 学習のスクリプトは利用者のコードなので, 骨組みは ML-EDA, ML-ModelControl, ML-Found, ML-Inference を使う形で書く (このライブラリ自身はそれらに依存しない)
- **他の段階との分け方**: 後ろの段階は, 問題の設定のファイルをこのライブラリを通して読む (YAML を自分で解釈しない). 段階どうしをつなぐかは, 要ると分かった所から段階ごとに決める (2026-11-18 の時点で, データの分析の ML-Fathom は「問題の設定から始める」と書き戻し, 推論の ML-Provide は一式に問題の設定をつないで損得を読む. 他の段階は利用者が受け渡しの値を見て画面で選ぶ). 受け渡しの値は, 各段階の約束と同じ名前と形で返す (意思決定は ML-Inference の `decision` の形そのまま, など)
- 依存は軽くする (PyYAML と pandas. pandas はデータのファイルから列の名前を読むためだけ). 前処理や学習はしない. 手元のデータから答えの候補を出す部分 (下の「データからの候補」) だけは ML-EDA を使う (任意の依存 `ml-quest[data]`. データの読み方は ML-EDA が持つ約束なので, 写して作り直さない)

## 用語

| 用語 | 意味 |
| --- | --- |
| 問題の設定 (problem) | 課題から, 決めること (行動), 機械学習の受け持ち, 損得, 確かめ方, 運用までを決めたもの. `problem.yaml` |
| 受け持ち (part) | 課題から見た, 機械学習の最後の出力の役 (予測する, 作る, 並べる, まとめる, 効果を見積もる) と, それに続く答え. `ml.parts` の 1 つ |
| 問い (question) | 問題の設定の 1 つの項目を埋めるための問い. 識別子は項目の場所 (`issue.pain` など) |
| 確かめ (finding) | 答えの食い違いや足りなさ. 重さは `error` (後ろの段階に渡せない), `warning` (渡せるが見直したい), `info` (知らせ) |
| 受け渡し (handoff) | 後ろの段階ごとの, 問題の設定から決まる値 |
| 骨組み (skeleton) | ML-Found のプロジェクトの形の, config と学習のスクリプトの雛形 |

## 問題の設定の形 (版 2)

```yaml
format_version: 2
name: 総菜の作る量                 # 問題の名前
created_at: "2026-11-17T21:30:00+09:00"
updated_at: "2026-11-17T21:45:00+09:00"

issue:                            # 1. 課題
  owner: 店長                     #    誰の課題か
  pain: 総菜の廃棄が多く, 夕方には品切れも出る
  current: 前の週の同じ曜日と同じ数を作る   # 今のやり方
  kpi:                            # 2. 解けたと言える指標
    name: 廃棄と欠品の損
    unit: 円 / 月
    current: 1200000              #    今の値 (分かれば)
    target: 960000                #    目指す値
    better: lower                 #    lower (小さいほど良い) か higher
  guard:                          #    守る指標 (任意. 引き換えに悪くしてはいけない数字)
    name: 品切れした品と日の割合
    unit: "%"
    better: lower                 #    向き (名前を書いたら要る)
    line: 5                       #    守る線 (これを割ったら失敗. 名前を書いたら要る)
    measure: 閉店の 2 時間前に棚が空の品と日を数える

decomposition:                    # 3. 課題の分解 (要因と打てる手)
  - cause: 作る量が勘で決まる
    lever: 作る量を売れる数の予測から決める
    ml: true                      #    機械学習で手伝う手か
  - cause: 夕方の値引きが遅い
    lever: 値引きの時刻を決めておく
    ml: false

ml:                               # 5. 機械学習の受け持ち
  use: true                       #    false なら機械学習を使わない (reason に理由)
  reason: 品と日による売れ方の違いが大きく, 今のやり方では追えない
  constraints: []                 # 7. 機械学習の仕組みが守る制約 (任意. 文の並び)
  parts:                          #    受け持ちの並び (今は 1 つだけ書ける)
    - role: predict               #    受け持ち (下の表)
      unit: row                   #    1 件の単位
      output: value               #    出力の形
      target:                     #    正解
        source: column            #      正解の出どころ
        process: null             #      今の処理の出力なら, その処理 (name, settings)
        kind: column              #      正解の種類 (予測すると作るで問う)
        column: sales             #      目的の列 (正解の種類が column のとき)
      method: scratch             #    作り方
      what: 翌日の品ごとの売れる数   #    何を出すか (文)
      item: 店, 品, 日ごとの 1 行   #    1 件は何か (文)
      task: forecasting           #    列の正解の種類 (classification, regression, forecasting)
      positive: null              #    2 クラスの分類で当たりのクラス
      group_column: null          #    同じ相手の行をまとめる列 (任意. 分割をまたがせない)
      split_time_column: null     #    分類と回帰を時刻の順で分けて確かめるときの時刻の列 (任意)
      time_column: date           #    時刻の列 (forecasting では必須)
      series_by: [store, item]    #    系列を分ける列
      available_lag: 2            #    決める時点で目的の値は何期前の分まで分かるか (forecasting で必須)
      horizon: 1                  #    何期先まで予測するか (forecasting で必須)
      baseline: 前の週の同じ曜日と同じ数   # 機械学習を使わない比べる相手
      consumer: rule              #    出力の使い道 (任意. human, rule, system, model, deliver)
      downstream: null            #    後段が求める形と精度 (system と model のとき)
      evaluation:                 # 8. 最良のモデルを選ぶ指標
        metric: mae               #    受け持ちと正解の種類ごとの候補か other
        name: null                #    other のときの名前 (監視する指標 valid/<名前>)
        better: null              #    other のときの向き (lower か higher)
        link: 誤差が小さいほど作る量の外れが減り, 廃棄と欠品の損が減る

data:                             # 5. 手元のデータ (任意. ML-EDA の読み方)
  source: /data/sozai.csv         #    データの場所 (絶対パス. 写したなら写しの場所で, origin に元の場所)
  loader: csv                     #    ML-EDA の読み込みの種類と設定 (Data.source と同じ)
  options: {time_column: date}
  missing: [天気予報の記録]        # 6. 要るのに手元に無いデータ

information:                      # 6. 予測の時点で使える情報 (columns は 5 で問う)
  columns: [date, store, item, sales, temperature_forecast, promo, customers]
  known: [store, item, temperature_forecast, promo]   # 予測の時点で分かる列
  unknown: [customers]            #    分からない列 (学習に使わない)
  forbidden: []                   #    分かっていても使ってはいけない列 (ID, 個人の情報など)

action:                           # 4. 決めること (機械学習を使うかに関わらず問う)
  who: 店長
  when: 前の日の 17 時
  what: 品ごとの作る量
  decision:                       # 7. 損得と制約 (ML-Inference の decision の形)
    type: quantity
    under_cost: 200
    over_cost: 150
  basis: 欠品は粗利 200 円, 廃棄は原価 150 円   # 損得の値の根拠

verification:                     # 9. 効果の確かめ方
  method: both                    #    backtest (過去のデータでたどり直す), trial (実際に試す), both
  backtest: 過去 3 か月で, 今のやり方と損を比べる
  trial: 1 店で 4 週間
  success: 廃棄と欠品の損が今のやり方より 2 割少ない

operation:                        # 10. 運用
  review: 月に 1 回
  approver: 本部
  stop: 損が今のやり方より悪い月が 2 回続いたら止める
  remeasure: 月に 1 回, 前の月の実績で外れ方を確かめ, 本部が承認したら書き戻す
```

- 上から順に決める. 各項目は次の項目の根拠になる (課題が無ければ指標は決まらず, 指標が無ければ機械学習の受け持ちの良し悪しは決まらない)
- 番号は問いの順 (4 の決めることと 7 の損得は `action` に一緒に置く. 損得は行動の結果の値なので. そのためファイルでは `action` が後ろにある). ただし使えるデータの列 (`information.columns`) は, 目的の列を選ぶ前に要るので 5 で問う
- 何を決めるか (4) は, 機械学習に何を出させるか (5) より先に問う (2026-11-18 にユーザーと決めた). 予測は決めるために使うもので, 予測を先に問うと「予測できそうなものを予測する」逆向きの考え方を誘うため. 機械学習を使わない場合も問う (決めることは課題を解くために要る). そのため, 前の版で作った機械学習を使わない問題の設定は, 4 の 3 つの問いが足りない誤りになる (答えれば直る)
- `ml.use` が `false` なら, 1 から 4 と, 使うかとその理由の他は要らない (機械学習を使わない出口. 代わりの手の確かめ方や運用は, このライブラリの対象外)
- 系列を分ける列と時刻の列も, 予測の時点で分かって学習に使うなら `known` に入れる (店や品のワンホットなど)
- 決める時点で分かる目的の値 (`available_lag`) は, 予測の時点で使える列と同じく漏れを防ぐための答え. 前の日の 17 時に翌日を決めるなら, 前の日の値はまだ確定しないので 2. 学習に 1 期前の値を使うと, 学習とたどり直しでは当たり, 使うときは外れる (ML_tester の 21 で, 1 期前を使うと今のやり方との差が 41.8 % に, 2 期前からにすると 38.6 % になった)
- `action.decision` は ML-Inference の意思決定の形 (`type` は `quantity`, `select`, `triage`, `none`) と同じ. `none` は予測を見て人が決める場合 (意思決定の材料を作らない). 対象を選ぶ型は, 効果の渡し方 (`effect_kind`: `share` 防げる割合 (既定) か `uplift` 行動したとき − しないときの当たりの確率) と, `uplift` の向き (`effect_goal`: 当たりを減らしたいなら `reduce`, 増やしたいなら `raise`) も書ける. 効果のモデル (介入の記録から学ぶ) の見積もりを, 確率を二重に掛けずに渡すため
- 知らない項目は残す (読む側は無視する). 版を上げるのは, 項目を消すか, 名前, 意味, 値の型を変える場合

### 受け持ちと, 型に依らない 5 つの問い

1 つのファイルに課題は 1 つ. 機械学習の受け持ちは並び (`ml.parts`) で持つが, 今は 1 つだけ書ける (2 つ以上は確かめの `error`. 2026-11-19 にユーザーと決めた. 次の段で「複数を書けるが段どうしはつながず, 受け持ちごとに別々に渡す」にする). 守る指標, 確かめ方, 運用は課題に 1 つなので受け持ちの外に置く. 問いの識別子は項目の場所なので, 受け持ちの問いは `ml.parts.0.role` のように並びの番号を持つ (`get_value` と `answer` は並びの番号をたどる).

5 の節の頭で, 型に依らない 5 つの問いを問う. 型ごとに続く問いは `when` で分ける.

| 問い | 場所 | 値 |
| --- | --- | --- |
| 受け持ち | `role` | `predict` 予測する (正解が 1 つに決まるものを当てる. 構造のある出力と異常も), `generate` 作る (正解が 1 つに決まらない中身), `rank` 並べる (候補から要求に合うものを順に), `group` まとめる (正解の無いデータをまとまりに), `effect` 効果を見積もる (行動したときとしないときの差) |
| 1 件の単位 | `unit` | `row` 行, `bundle` まとまり (撮影, 文書と添付), `pair` 対 (入力と正解のファイル), `query` 要求と候補の組, `collection` 集まり (文書の束), `window` 時間の窓 |
| 出力の形 | `output` | `class` クラス, `value` 値, `distribution` 分布 (分位点, 区間), `region` 位置や領域, `shape` 3D の形, `text` 文, `image` 画像, `table` 表, `ranking` 順位, `cluster` 群, `effect` 行動ごとの差 (受け持ちに合うものだけを選択肢に出す) |
| 正解の出どころ | `target.source` | `column` データの列, `files` 対のファイル, `self` 自分自身 (隠して当てる, 元に戻す), `none` 無い, `few` 少し (確かめの組だけ), `process` 今の処理の出力, `objective` 目的の式, `feedback` 行動の結果, `intervention` 介入の記録, `human` 人の判断と好み, `instruction` 指示と例 |
| 作り方 | `method` | `rule` 規則, `pretrained` 既製のモデルをそのまま, `head` 既製の特徴の上に頭だけ学習, `partial` 一部を微調整, `finetune` 全体を微調整, `scratch` 一から学習 |

- 正解の出どころが今の処理の出力 (`process`) なら, その処理の名前 (`target.process.name`. 要る) と設定 (`target.process.settings`. 任意の文) を問う. 何で作ったかは問わないが, 評価と結論で「その処理を超えられない」ことを示せるように残す (2026-11-19 にユーザーと決めた)
- 正解の種類 (`target.kind`) は予測すると作るで問う: 予測するは `column` 表の列 (クラスか値), `mask` 画像の領域, `point_cloud` 点群, `text` 文. 作るは `text`, `image`, `table` 表 (合成のデータ), `point_cloud`
- 続く問い: 予測するで正解の種類が表の列のとき (以下「列の予測」) だけ, 版 1 の問い (タスク, 目的の列, 当たりのクラス, 時刻の列など), 使える列 (`information`), 意思決定の損得と今のやり方と根拠 (`action.decision`, `action.current`, `action.basis`) を問う. 並べる, まとめる, 効果を見積もるの受け持ちの中の問いは, 5 つの問いと何を出すか, 1 件は何か, 比べる相手, 使い道, 最良を選ぶ指標だけ (型ごとの通り道は下の「課題の型への広げ方」の進め方の 4). 受け持ちに依らない問い (手元のデータ, 要るのに無いデータ, 制約, 9 と 10 の節) は全ての受け持ちで問う
- タスク (`task`) は列の正解の種類 (分類, 回帰, 時系列の予測) に限る (2026-11-19 にユーザーと決めた). 型は受け持ち (`role`) と正解の種類 (`target.kind`) で表す

### 最良を選ぶ指標

学習の損失 (交差エントロピー, KL ダイバージェンスなど) は問わない. モデルの作成と学習の段階で決める (2026-11-19 にユーザーと決めた). 問うのは, 検証用の分割で最も良いモデルを選ぶ指標 (`evaluation.metric`). 候補は受け持ち, 正解の種類, タスクごと.

| 受け持ちと正解の種類 | 候補 (向き) |
| --- | --- |
| 予測する, 表の列, 分類 | `accuracy` (大きい), `loss` 交差エントロピー (小さい) |
| 予測する, 表の列, 回帰と時系列の予測 | `mae` (小さい), `rmse` (小さい) |
| 予測する, 画像の領域 | `iou` (大きい), `loss` (小さい) |
| 予測する, 点群 | `chamfer` (小さい), `loss` (小さい) |
| 予測する, 文 | `cer` 文字の誤り率 (小さい), `loss` (小さい) |
| 作る | `loss` (小さい). 画像は `fid` (小さい) も |
| 並べる | `recall_at_k` (大きい), `ndcg` (大きい), `loss` (小さい) |
| まとめる | `silhouette` (大きい), `loss` (小さい) |
| 効果を見積もる | `qini` (大きい), `loss` (小さい) |
| 全て | `other` その他 (名前 `evaluation.name` と向き `evaluation.better` を書く) |

- 監視する指標は `valid/<指標>` (RMSE は並びの同じ `valid/mse`). その他は `valid/<名前>`. 名前は英数字と `_`, `.`, `@`, `-` だけ (`.` と `..` は除く. 学習の記録の名前と曲線のファイルの名前になるため)
- `loss` は `METRICS` に 2 つある (分類の交差エントロピーと, 他の受け持ちの損失. 監視する名前が同じ `valid/loss` なので値も同じ). 画面は `METRICS` を直接使わず, `questions` の `choices` (今の答えで絞り, 同じ値は 1 つ) を使う
- 指標をその他から変えた後の名前と向きは, 他の要らなくなった問いの古い答えと同じく, ファイルに残すが使わない (受け渡しは要る問いの答えだけを読む)
- 列の予測の出力の形は `class`, `value`, `distribution` のどれか (他は `error`)
- 版 1 のファイルの指標は 4 つ (`accuracy`, `loss`, `mae`, `rmse`) のまま読め, 版 1 のファイルにそれ以外 (`other` も) を書くと「知らない指標」の誤り. 版 2 から候補と `other` を書ける. 版 1 の 4 つの他の指標は移さず, 版 1 の場所 (`evaluation.metric`) に残す (確かめで「知らない指標」. 最良を選ぶ指標に答えると消える)

### 版と, 版 1 から移す

- 版 1 は「1 件の値を表の列から予測する」課題だけを書けた (`ml` の直下にタスクや目的の列, 学習の指標は `evaluation`). 版 2 で受け持ちごとの項目を `ml.parts` に移した
- `upgrade_problem(problem)` は版 1 を版 2 に移す (元は変えない. 版 1 に手で書いた受け持ちがあれば, その答えは上書きしない. 受け持ちの並びが崩れていれば移さず, 確かめで形の誤り). 版 1 の値は全て移る: `ml.predict` → `what`, `ml.row` → `item`, `ml.target` → `target.column`, `ml.task`, `ml.positive`, `ml.group_column`, `ml.split_time_column`, `ml.time_column`, `ml.series_by`, `ml.available_lag`, `ml.horizon`, `ml.baseline`, `ml.consumer`, `ml.downstream` は同じ名前で受け持ちの中へ, `evaluation.metric` と `evaluation.link` は受け持ちの `evaluation` へ. `ml.use`, `ml.reason`, `ml.constraints` と他の節はそのまま. 知らない項目もそのまま残す
- 版 1 が前提にしていた答えは, 移すときに埋める: 受け持ちは `predict`, 1 件の単位は `row`, 正解の出どころと種類は `column`, 作り方は `scratch` (版 1 の通り道は, 表の列を一から学習する骨組みだけだったため), 出力の形はタスクから (分類は `class`, 他は `value`). 受け持ちを作るのは, 機械学習を使うか, 受け持ちの項目が 1 つでもある場合だけ
- **先に移す**: 問い, 答え, 確かめ, 受け渡し, 要約, 書き戻し, データの候補, 骨組みは, 版 1 の問題の設定を受け取ると先に版 2 に移して扱う (返す問題の設定は版 2). 版ごとに 2 通りの確かめを持たないため. `load_problem` も読んだ後に移す (ファイルは書くまで版 1 のまま)
- 版 1 の場所の名前 (`ml.target`, `ml.task`, `evaluation.metric` など) は, 版 2 の問題の設定でも `get_value`, `active_value`, `answer` で使える (移した先を読み書きする). 後ろの段階が版 1 の名前で読んでいても壊れないように
- 版が 1 以上の整数でない問題の設定 (文字列, 小数, 真偽値, 0) も, 読み込みと同じく誤り
- 知っている版より新しい版は読まない. `load_problem` と, 問題の設定を受け取る関数は誤り (`ValueError`) で止まり, `check` は版の誤りだけを返す (読める項目だけを使うと, 黙って読み違えるため)

## 問い

`questions(problem)` は, 問いの並びを, 今の答えと, 答えたか, 今は要らないか (`ml.use` が `false` の場合の `ml.target` など) と一緒に返す. 画面はこれを上から順に出す.

| 問いの種類 (`kind`) | 答えの形 |
| --- | --- |
| `text` | 文 |
| `number` | 数 |
| `choice` | 決まった選択肢の 1 つ (`choices` に値と説明. 今の答え (受け持ち, 正解の種類, タスク) に合うものだけ) |
| `boolean` | はいかいいえ |
| `column` | データの列の名前の 1 つ (`information.columns` から) |
| `columns` | データの列の名前の並び |
| `list` | 文の並び |
| `levers` | 要因と打てる手の並び (`decomposition`) |
| `decision` | 意思決定の型と損得と制約 (ML-Inference の形). `choices` は型ごとに名前と欄 (`fields`: `key`, `label`, `required`, 選んで書く欄は `choices` と選ばないときの意味 `unset`, 他の欄の値で要るかが決まる欄は `when`) を持ち, 画面はこれだけで描く |
| `baseline` | 今のやり方をデータで書いたもの (`type` と `periods` か `column`. 上の「今のやり方をデータで書く」) |
| `source` | データの場所 (絶対パス. `~` は展開する). 画面はファイルを選ばせて `attach_data` で入れる (`answer` で場所だけを答えると, 読み方と列の名前は入らない) |

- 各問いは `id` (項目の場所), `section` (1 から 10), `title` (問い), `help` (なぜ問うか, 例), `required`, `kind` を持つ. `when` (条件の並び. 全てを満たすときに要る. 条件は, 項目の値が等しい `equals`, 並びに入る `in`, 答えたか `filled`) で, 今の答えのもとで要るかが決まる (機械学習を使う場合だけ, 受け持ちごと, 列の予測だけ, 分類だけ, 時系列の予測だけ, など)
- 要らなくなった問いの古い答え (タスクを回帰に変えた後の時刻の列など) は, ファイルには残すが, 確かめ, 受け渡し, 要約, 骨組みでは使わない
- `answer(problem, id, value)` は, 答えの形を確かめて問題の設定に入れ, 新しい問題の設定を返す (元は変えない). 形の誤りは `ValueError`. 空 (None や空の文字列) は答えを消し, 空になった親の項目も消す. 文の答えは, 行ごとに続く空白を 1 つにし, 改行は残す (続く空の行は 1 つに)
- 損得の値は数か列の名前. 数として読める文字列 (`1e3`, `+5`, 桁区切りの `1,200`) は数にし, 数に見えて読めない文字列 (`1,2,3`, `-`) と無限大, 非数は誤り. それ以外の文字列は行ごとの値の列の名前で, 使えるデータの列にあるかを確かめで見る
- 列の名前は, 利用者が選んだデータのファイルから `read_columns(path)` で読む (csv と tsv は 1 行目だけで, UTF-8 で読めなければ Shift_JIS. parquet は形の情報だけ (pyarrow が要る). Excel は openpyxl が要る). 同じ名前の列と空のファイルは誤り

## データからの候補

課題, 指標, 分解, 決めること (1 から 4) はデータ無しで答える. 手元のデータから考え始めると, 技術の側から組み立てて「このデータで何が予測できるか」になりやすいため. データは 5 (機械学習の受け持ち) で入れ, 後の問いの答えの候補と確かめに使う. 手元のデータが課題に要るデータとは限らないので, 要るのに無いデータ (`data.missing`) も書ける (まずデータを集める, という結論もありうる).

- `attach_data(problem, path)` は, ML-EDA の `load_data` でデータを読み, 読めた種類と設定 (`Data.source` の `loader` と `options`. 時刻の列は除く), ファイルの大きさと更新の時刻, 場所を `data` に, 列の名前を `information.columns` に入れた新しい問題の設定を返す. データは写さない. 読み方の指定 (Excel のシートなど) は次の段階
- 時刻の列は読み方に持たず, 読むたびに答え (`ml.time_column`) から付ける. まず ML-EDA の推定で読み (系列を分ける列も推定される), 推定した時刻の列が答えと違うときだけ, 答えた列を日時の列に指定して読み直す (店と品のように系列を分ける列が複数あると推定できないため). 答えた列がデータに無ければ指定せずに読み, 確かめで知らせる
- `inspect_data(problem)` は, 入れたデータを同じ読み方で読み直し, ML-EDA の `profile` (目的の列を答えていればそれとの関係も) から次を返す. 重いので `check` とは分け, 画面は必要なときに呼ぶ
    - 概要: 行の数, 列の数, 種類 (表か時系列), 時刻の範囲と間隔
    - 概要には, ML-EDA が大きなデータを見本の行で分析したか (`sampled`) も入れる (読み込みは全体)
    - 答えの候補 (問いの識別子ごとの値の並びと理由. 押せば答えになる値だけ): 目的の列 (答えたタスクに合う型. 回帰と予測は数, 分類は種類の少ない列. ID のような列, 定数の列, 時刻と系列の列は除く), タスク (まだ答えていなければ, 目的の列の型と時系列か), 当たりのクラス (分類の目的の列の全ての値), 時刻の列 (日時の列), 系列を分ける列 (数でない列のうち, 同じ時刻に複数の値が並び, 時刻と組にするとほとんど重ならない列), 使ってはいけない列 (ID のような列. `id_like`)
    - 確かめ (`check` と同じ形): 行が少ない (100 行未満), 入れた後にファイルが変わった, 使えるデータの列とデータの列が違う, 答えた時刻の列や目的の列がデータに無い, 当たりのクラスがデータの値に無い (全ての値で. 1 と 1.0 は同じ), 答えたタスクと目的の列の型の食い違い (知らせ), 漏れの疑い (目的の列とほぼ同じ動きの列. ML-EDA の `target_leak`. 予測の時点で分かるなら使ってよいので, 値は入れさせず確かめてもらう), 何期先までがデータの期間に比べて長い (データの間隔で数えた目安), データが読めない. ML-EDA の気付きは問題の設定に関わるもの (目的の列の欠損, クラスの偏り, 多い欠損, 重複, 時刻の間隔) だけを重さのまま添える
- 受け渡しのデータの分析の値に, データの場所と読み方 (`source`) を入れる (全体のシステムでは ML-Fathom が同じ読み方で開く想定)
- データは写して持つ (2026-11-17 にユーザーと決めた). `attach_data(problem, path, copy_to=...)` は, 写し先を渡すとファイル (かディレクトリ) を写し, `data.source` を写した場所, `data.origin` を元の場所にする. 画面は問題の設定ごとの置き場に写す. `make_project` は, データを入れていればプロジェクトの `data/` に写し, プロジェクトの問題の設定の `data.source` をそこにする (学習のプロジェクトだけで, データの分析から学習までをやり直せるように). 写しも上書きの確かめの対象. 写し先が相対パスか元のディレクトリの中なら誤り. 元の場所は `..` などを正規化してから写し, 写しが写し先の外に出ないことを確かめる. `attach_data` は入れるたびに写し先の中の別のサブディレクトリに写す (入れ直したファイルが読めなくても今の写しが残る). 同じ元のファイル (`data.origin` が同じ) で大きさと更新の時刻 (ナノ秒) が変わっていなければ今の写しを使う. 古い写しは `prune_copies(写し先, 今の場所)` で片付ける (画面は保存の後に呼ぶ). 写す前に空きを確かめ, 一時の名前に写してから置き換え, 失敗したら一時の写しを消す. ディレクトリの中のリンクは指す先を写す (元から独立). 古い写しの片付けは attach_data が作った名前 (12 桁の 16 進) のサブディレクトリだけで, 写し先に置いた他のファイルは消さない. 写し先そのものはデータにできない. 写し先の中のファイルを入れた場合, 元の場所は前と同じ場所のときだけ引き継ぐ. 読めなければ新しい写しを消す. 写しが消えた場合 (置き場の問題の設定を消したなど), 受け渡し, 分析, 骨組みは `data.origin` を使う (`data_location`)

### 今のやり方をデータで書く

指標の今の値に根拠を持たせるため, 今のやり方 (1 の「今はどうしていますか」) をデータの上で書き表す問い (`action.current`. 7 の損得と制約の後) を置く (2026-11-17 にユーザーと決めた). 答えの形は種類ごと.

| 種類 (`type`) | 意味 | 使える行動の型 |
| --- | --- | --- |
| `lag` | k 期前の目的の値と同じ (例: 前の週の同じ曜日と同じ数. `periods: 7`) | 量を決める |
| `mean` | 直前の k 期の目的の値の平均 | 量を決める |
| `column` | データの列に今のやり方の値がある (量なら置いた量, 選ぶと振り分けなら行動したか) | 全て |

- k 期前と平均は, ML-EDA の時刻でずらす手順 (`lag` の `time` と `freq`) と同じ扱いで数える (1 期はデータの時刻の間隔. 休みで日が飛んでも暦の k 期前. 系列を分ける列があれば系列ごと). 時刻の列が無ければ求めず, 今のやり方の値の列で書くよう知らせる. 平均は窓に値が 1 つでもあれば求める (ML-EDA と同じ)
- 損得の値か今のやり方が欠けた行は除く. 行動したかの列は, 数は 0 より大きいか, 文字は yes や はい などで読み, 読めない値は除く
- `inspect_data` は, データの上で今のやり方の実際の損 (量と振り分け) を, 問題の設定の損得で求め, データの期間 (時刻の列があれば日数と 30 日あたり. 1 日に満たなければ 30 日あたりは出さない) とともに返す. 指標の単位がお金 (円) か, まだ書いていなければ, 指標の今の値の候補 (`issue.kpi.current`) にも出す. 対象を選ぶ行動の得は求めない (行動した行の結果は行動の後の値で, 行動しなかった場合が分からないため. 試して確かめる). 求められない場合は理由を知らせる

## 後ろの段階との書き戻し

全体のシステムでは, データの分析の段階 (ML-Fathom) が問題の設定のデータを開くとき, 目的の列, タスク, 分割, 除く列を決めた状態で始め, そこで変えた選び方は問題の設定に書き戻す (2026-11-17 にユーザーと決めた). つなぐための部品はこのライブラリに置き, ML-Fathom の「問題の設定から始める」が使う (2026-11-18 につないだ).

- `recipe_from(problem)` は, データの読み方 (場所, 読み込みの種類と設定, 時刻の列) と, ML-EDA のレシピの雛形を返す. 雛形は, 受け渡しの値から, 目的の列, タスク, 除く列の `drop_columns` の手順, 時系列なら系列ごとの過去の値の手順 (`lags` は決める時点で分かる最も新しい期. 時刻の間隔 (`data.interval_seconds`. データを入れたときに求める) が分かれば `time` と `freq` で時刻でずらし, 分からなければ行でずらして知らせる), 分割 (時系列は時刻の順, 相手をまとめる列があれば相手ごと, 分類は層別, 他は無作為. 相手の列は時刻の順でも `split.column` に書く. 時刻の順で列を書けるのは ML-EDA #29 から). 書き戻したレシピの `split.column` と `ml.group_column` が違えば, 書き戻しの食い違いと `recipe_from` の知らせに出す. 前処理の残りの手順 (欠損, ワンホット, 標準化など) はデータの分析の段階で足す. 書き戻したレシピがあれば (`data.recipe`), それを返す (往復で同じになる)
- `apply_recipe(problem, recipe)` は, データの分析の段階で決めたレシピを問題の設定に書き戻す. 自動で書き戻すのは目的の列とタスクだけ (新しい目的の列は列の使い方から外し, 元の目的の列は決め直すよう知らせる). 列の使い方は方針なので黙って変えない: 使ってはいけない列をレシピが使っていれば食い違い (`error`), 分からない列をレシピが使っていれば, 分かる列に移すかレシピで落とすかを利用者が選ぶ問い (`choices`) にする (自動にできない判断は選ばせる). レシピの過去の値が決める時点で分からない期から始まる場合と, 時系列の予測で分割が時刻の順でない場合も食い違い (`warning`). 目的の列を落とす手順は誤り. 目的の列を変えたレシピが前の目的の列を使っていれば, 分かる列にするか落とすかを選ぶ問いにする (黙って特徴にしない). 落とすと選んだ列は, 過去の値の手順の他の手順 (ワンホット, 欠損の埋めなど) の対象から外し (対象が無くなった手順は除く), レシピの最後の落とす手順で元の列を落とす (過去の値は決める時点で分かるので残す. 前の手順がその列を使っても失敗しないように). 前の目的の列の問いは落とすを先に出す (予測したい値そのものは, ふつう予測の時点で分からない). レシピそのものは `data.recipe` に持つ. 返すのは書き戻した問題の設定, 変えた点の文, 食い違い, 選ぶ問い
- `resolve_choice(problem, column, option)` は選ぶ問いに答える (`known` で分かる列に移す, `drop` で書き戻したレシピの落とす列に足す)

## 確かめ

`check(problem)` は確かめの一覧を返す. 項目の場所と, 重さと, 何をすればよいかの文を持つ.

- **形**: 手で書いたファイルで, 値の形が崩れている (並びでない受け持ち, 辞書でない受け持ち, 知らない受け持ち, 1 件の単位, 出力の形, 正解の出どころ, 正解の種類, 作り方, その他の指標の向き, 版 1 のファイルの 4 つ以外の指標, 知らない意思決定の型やタスクや指標, 文字列でないタスク, 目的の列, 時刻の列, 当たりのクラス, 指標, 列の名前の並びでない値, 辞書でない分解の行, 文字列でない使い道と後段と守る指標の名前, 知らない使い道, 文の並びでない制約) (`error`. この場合は他の確かめをしない)
- **受け持ちの数**: 受け持ちが 2 つ以上 (`error`. 今は 1 つだけ書ける. 形の誤りと同じく他の確かめをしない)
- **知らない版**: 版が 1 以上の整数でないか, 知っている版より新しい (`error`. 他の確かめをしない)
- **足りない答え**: 今の答えのもとで要る問いの空 (`error`). 機械学習を使わない場合は, 1 から 4 と, 使うかとその理由だけを要る
- **筋道**: 機械学習で手伝う手 (`decomposition` の `ml: true`) が無いのに `ml.use` が `true` (`warning`. 何を手伝うのかが分からない). 指標の今の値と目指す値の向きが `better` と逆 (`error`)
- **タスクと行動**: `quantity` は回帰か予測, `select` と `triage` は分類で `positive` が要る (`error`). 分類で `positive` が無く, 行動が `none` 以外 (`error`)
- **時刻**: `forecasting` で `time_column`, `available_lag`, `horizon` が無い (足りない答え). 時刻の列が目的の列か, 系列を分ける列か, 使わない列に入っている. `horizon` と `available_lag` が 1 以上の整数でない (`error`)
- **列の答え直し**: 目的の列, 時刻の列, 系列を分ける列, 使う列と使わない列が, 使えるデータの列に無い (`error`. 列を答え直した後の古い名前)
- **使ってよい列**: 目的の列が `known` に入っている (予測の時点で分かるなら予測は要らない. 時系列で過去の値を使う場合は, 過去の値の列は後でデータの分析の段階で作るので, 目的の列そのものは `known` に入れない) (`error`). `known` と `unknown` の重なり (`error`). `columns` にあるのに `known` にも `unknown` にも無い列 (`warning`. 使ってよいか決めていない)
- **今のやり方**: 選ぶと振り分けを k 期前か平均で書いた (`error`). 今のやり方の列を学習に使ってよい列にした (`warning`. 今のやり方の結果は予測の後に決まる). 量の型で今ある量があり, 今のやり方を列で書いた (`info`. 推論のたどり直しには渡さない)
- **損得**: 損得の値が 0 以下 (今ある量は負. 効果は 0 から 1 の外. `uplift` の効果は -1 から 1 の外) (`error`). `uplift` で向きが無い, `uplift` でないのに向きがある, 知らない渡し方と向き (空は既定の `share`), 手で書いた型に無い項目 (`error`). 列の名前で書いた値が使えるデータの列に無い (`error`. あれば行ごとの値として読む `info`). 根拠 (`basis`) が空 (`warning`. 根拠の無い損得では, 意思決定はもっともらしいだけになる). 対象を選ぶ型の効果は仮定 (`info`. `uplift` では見積もりで, 行動を無作為に割り当てて試して確かめる)
- **受け持ちの答え**: 受け持ちに合わない出力の形と正解の種類 (`error`. 選択肢に無い値). 分類で出力の形がクラスでない, 回帰と予測で出力の形がクラス (`warning`)
- **指標**: 最良を選ぶ指標が受け持ち, 正解の種類, タスクに合わない (`error`). その他の名前に空白か `/` がある (`error`). 指標と KPI のつながり (`link`) が空 (`warning`)
- **確かめ方と運用**: 確かめ方が空 (`error`). 対象を選ぶ型をたどり直しだけで確かめる (`warning`. 行動の効果は試さないと分からない). 止める条件が空 (`warning`)
- **使い道**: 予測を決まりで自動に決めるのに意思決定が `none` (`warning`). 後段の仕組みか機械学習に渡すのに, 後段が求めるもの (`ml.downstream`) が空 (`warning`. 評価は後段の結果で見るため)
- **守る指標**: 手で書いた, 数でない守る線と知らない向き (`error`). 解けたと言える指標と同じ名前 (`warning`). 機械学習を使うのに, 守る指標の名前が成功の基準 (9) にも止める条件 (10) にも無い (`info`. 良くしたい数字だけを追わないように. 名前がそのまま入っているかで見るので, 言い換えると出る)
- **その他の筋道**: 目指す値が今の値と同じ (`warning`), 分解の全ての手が機械学習 (`info`. 機械学習を使わない手と比べられない), 使わないと決めたのに機械学習で手伝う手がある (`info`)

## 受け渡し

`handoff(problem)` は後ろの段階ごとの値を返す. 確かめに `error` があれば誤り.

| 段階 | 値 | 使い方 (今は利用者が各段階の画面で選ぶ) |
| --- | --- | --- |
| データの分析 (ML-EDA, ML-Fathom) | `target`, `task`, `time_column`, `series_by`, `split` (予測と, 分類と回帰で時刻の順で分ける列 (`ml.split_time_column`) があれば `time`, 相手をまとめる列があれば `group`, 分類は `stratified`, 他は `random`. レシピの下書きの分割と同じ. 時刻の列は `time_column` で渡し, 学習に使わない列にしてもよい), `group_column` (相手をまとめる列. 時刻の順でも渡し, ML-EDA が分割をまたぐ重なりを知らせる), `min_lag` (過去の値の列に使ってよい最も小さいずらし幅. 予測だけ), `known` (学習に使ってよい列), `drop` (`unknown` と `forbidden` の列) | 読み込みの日時の列 (`load_data` の `time_column`. 系列を分ける列が複数あると ML-EDA は日時の列を推定できない), レシピの目的の列, タスク, 分割, 除く列 |
| 受け持ち | `part` (`role`, `unit`, `output`, `target_kind`, `target_source`, `target_process`, `method`) | 型に依らない 5 つの答え |
| モデルの作成 (ML-ModelControl, ML-CreateArchitecture) | `task`, `outputs` (回帰と予測は 1, 分類はクラスの数. 分からなければ空), `role`, `target_kind` | 出力の大きさ |
| 学習・評価 (ML-Found, ML-Dashboard) | `metric`, `monitor` (`valid/<指標>`. RMSE はバッチの平均で書けないので, 並びの同じ `valid/mse`. その他は `valid/<名前>`), `mode` (`min` か `max`), `role`, `target_kind` | config の `trainer.monitor` と `trainer.mode` |
| 推論 (ML-Inference, ML-Provide) | `decision` (損得と制約. 選ぶと振り分けには `ml.positive` を `positive` として足す. 今のやり方 (`action.current`) が列なら, たどり直しで比べる `current` として足す. ただし量の型は今ある量 (`stock`) が無いか 0 の場合だけ (ML-Inference の量の `current` は今ある量に足した量, 問題の設定の列は置いた量なので, 今ある量があると意味が違う). k 期前と平均は ML-Inference に同じものが無いので渡さない), `conclusion` (系列を分ける最初の列でまとめる `group_by`. 無ければ空), `horizon` (何期先まで) | 一式の既定値 (`make_bundle` の `decision` と `conclusion`), 何段も先の予測. ML-Provide は一式につないだ問題の設定から推論の既定値を読む |

最良を選ぶ指標の候補は, 上の「最良を選ぶ指標」.

- 受け持ちの答えは `part` (`role`, `unit`, `output`, `target_kind`, `target_source`, `target_process`, `method`) で渡す. 学習・評価とモデルの作成にも `role` と `target_kind` を足す (足しただけで, 列の予測の版 1 からの値は変えない)
- 列の予測でない受け持ち (予測するの点群など) は, データの分析の値を同じ名前の空 (`target`, `task`, `split` は `None`, 並びは空) にし, 意思決定は `None`, 結論は空, 何期先までは `None` で渡す. その型のデータの書き出しと推論の約束は, ML-EDA と ML-Inference の版を上げてから (進め方の 4)

## 骨組み

`make_project(problem, path)` は ML-Found のプロジェクトの骨組みを書き出す. 確かめに `error` があれば誤り. 既にあるファイルは上書きしない (`overwrite=True` で上書き).

```
<プロジェクト>/
├── problem.yaml                # 問題の設定の写し
├── README.md                   # 課題の要約と, 次にすること (データの分析, モデルの作成, 学習)
├── configs/
│   ├── default/train.yaml      # 指標から monitor と mode. データセットとモデルの定義の場所
│   └── experiment/train.yaml   # 空の差分
└── train.py                    # 学習のスクリプト
```

- 学習のスクリプトは, ML-EDA のデータセット (`outputs/dataset`) を読み, ML-ModelControl の定義 (`models/model.yaml`) からモデルを組み立て, ML-Found で学習し, テスト用の分割で評価し, ML-Inference の推論の一式を実験の中に作る (問題の設定の意思決定と結論を既定値にする)
- タスクごとの損失と指標: 分類は交差エントロピーと正解率 (正解率を監視するなら, 同じ値を損失で比べる `trainer.monitor_tiebreak: valid/loss`), 回帰と予測は目的の値を学習用の平均と標準偏差で標準化した二乗誤差と元の単位の平均絶対誤差 (RMSE なら元の単位の二乗誤差を監視し, テスト用の評価はエポック全体から RMSE を求める. ML-Found はバッチの平均で書ける指標だけを平均するため)
- 推論の一式の確かめが学習の記録と比べられるのは, 監視した指標が `accuracy` か `mae` の場合だけ (ML-Inference の決まり). それ以外では比べない理由を記録に書く
- 答えの文字 (名前, 予測すること, 比べる相手) は, JSON の文字列か 1 行のコメントとして埋め込む (改行や引用符でスクリプトが壊れないように). 実験の名前は目的の列とタスクから作り, 日本語の文字は残す
- 検証用の分割の無いデータセットは, 学習の前に止めて案内する (最も良いモデルを選べないため)
- 比べる相手 (`ml.baseline`) はデータによって作り方が違うので, スクリプトでは計算せず, 書き足す場所に印 (`TODO`) を残す
- 表と時系列 (学習に使う列の表) のデータを前提にする. 画像, 文, 点群は, データの読み方とモデルの入力を書き直す
- 列の予測だけを書き出す. 他の受け持ちと正解の種類, 最良を選ぶ指標がその他の場合は誤り (学習のスクリプトがその指標を記録できないため. 型ごとの骨組みは進め方の 4). レシピの下書き (`recipe_from`) と書き戻し (`apply_recipe`) も列の予測だけ
- `project_error(problem)` は, 書き出せない理由を `make_project` が出す誤りの文のまま返す (書き出せるなら `None`). 確かめる順は, 受け渡し (`handoff`), 列の予測か, 指標がその他でないか. `make_project` もこれを使う (画面が同じ決まりを写して持たず, 2 つが食い違わないように). 書き出し先の既にあるファイルは見ない
- 合成のデータで, 予測 (量を決める) と分類 (対象を選ぶ) の骨組みが, データセットの書き出しとモデルの定義を置けば学習から推論の一式まで通り, 一式の確かめが学習の記録と合うことを確かめた. 回帰で RMSE, 分類で正解率を監視する場合も通る
- 書く前に, 既にあるファイル (上書きしない場合) と, ディレクトリを作れない場所 (同じ名前のファイルがある, など) を全て確かめ, 1 つでもあれば何も書かずに誤りにする
- 骨組みは出発点で, 利用者が書き足す. 書き出した後の問題の設定の変更は, 骨組みには自動で反映しない (書き出し直すか手で直す)

## 書き出し

- `save_problem(problem, path)` は `updated_at` を今にして YAML で書く (一時ファイルに書いてから置き換える)
- `load_problem(path)` は読んで版を確かめ (版の無いファイルと, 知っている版より新しい版は誤り), 版 1 なら版 2 に移して返す

## 課題の型への広げ方 (2026-11-18 の方針)

今の問いは「1 件の値を予測し (分類, 回帰, 時系列の予測), 予測で業務の行動を決める」課題を前提にしている (タスクの 3 択, 目的は表の列 1 つ, 学習の指標 4 つ, 業務の指標 1 つ, 分割は時刻の順か無作為 (レシピの下書きでは分類を層別), 骨組みは表と時系列). 機械学習の課題は, 1 件の分からない値を当てる「予測する」(分類, 回帰, 時系列の予測. 検出, 領域分け, 文字起こし, 3D の形のような構造のある出力と, 正解のほぼ無い異常の検知も) のほかに, 正解が 1 つに決まらない中身を「作る」, 多くの候補から「並べる」(推薦, 検索), 正解の無いデータを「まとめる」(群分け), 行動の「効果を見積もる」(uplift, バンディットや強化学習の方策) に分けられる. 正解の出どころ (列, 対のファイル, 自分自身, 今の処理の出力, 行動の結果, 介入の記録, 指示 (プロンプト)), 1 件の単位 (行, まとまり, 対, 要求と候補, 窓), 作り方 (規則, 既製のモデルをそのまま, 頭だけ学習, 微調整, 一から) で, データの形と確かめ方が変わる (2026-11-18 に, モデルの系統と課題の事例を調べて決めた). 広げる順は, 約束 (ファイルの形の版) を変えずに出せるもの → 約束の版を上げるもの → 型ごとの通り道.

- 受け持ちは, 課題から見た機械学習の最後の出力に付ける 5 つ (予測する, 作る, 並べる, まとめる, 効果を見積もる). 今の時間のかかる処理を速くする「置き換え」は受け持ちにせず, 正解の出どころ (今の処理の出力), 守る指標 (今と同じ結果), 元に戻す道で書く. 埋め込み (表す) は段の部品で, 受け持ちにしない
- 1 つのファイルに課題は 1 つ. 受け持ちは並びで持つ (はじめは 1 つだけ許す. 守る指標と確かめ方は課題に 1 つ)
- 進め方
    1. 守る指標 (2 の節. 名前, 単位, 向き, 守る線, 測り方) と, 9 の節 (確かめ方) と 10 の節 (止める条件) へのつなぎ. 版 1 のまま (済み. はじめは 1 つ. 後ろの段階 (推論のたどり直しと測り直し) で守る指標を数えるのはまだ)
    2. 出力の使い道 (人が見る / 決まりで自動に決める / 後段の仕組み / 後段の機械学習 / そのまま届ける) と後段, 分割の単位の受け渡し (グループ, 層別, 分類でも時刻), 出力が幾何なら要る精度と 1 画素の実寸, 制約 (ライセンス, データを外に出せるか, 待ち時間). 版 1 のまま (使い道と後段 (要る精度は後段の問いの中で) と制約, 相手をまとめる列 (`ml.group_column`) の受け渡しは済み. 分類と回帰を時刻の順で分ける列 (`ml.split_time_column`), 分類の層別の受け渡しも済み)
    3. 問題の設定の形の版 2: 5 の節の頭に型に依らない 5 つの問い (受け持ち, 1 件の単位, 出力の形, 正解の出どころ, 作り方) を置き, 型ごとに続く問いを分ける. 最良を選ぶ指標は受け持ちと正解の種類ごとの候補とその他. 版 1 から移す関数を持つ (版 1 の値は全て埋まる) (済み. 2026-11-19 にユーザーと決めたとおり. 並べる, まとめる, 効果を見積もるの続く問いは最小限)
    4. 型ごとの通り道 (多視点の撮影から 3D を作り, 後段の規則で検査する課題を最初の実例に), 学習しない作り方, 骨組みを型ごとに, 段の並び (複数の受け持ち)
- 決めていないこと: 段どうしのつなぎの約束 (段の多い実例が出てから)
